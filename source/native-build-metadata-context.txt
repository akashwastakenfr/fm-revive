6cd503f The enumerate mode event allows a game to determine if a given output mode is supported.
6cd5099 On the PC platform, different PC's may support different modes based on the configuration of the PC software and hardware. On other console platforms, the modes supported will typically not change.
6cd5160 On the XBox One, PS3 and PS4 the mix may either be output as 7.1 or reformatted to something else based on the console dashboard settings (such as stereo or 5.1). In the case of a stereo console selection, ProLogic II can be output instead of stereo if set to this mode via EAAudioCore (EVENT_SETMODE).
6cd5290  On the Xbox 360, the mix will first be reformatted by the Dac PlugIn to 5.1 channels if it isn't already in that format. It may be further reformatted by the console to the selected output mode, such as mono, stereo, or ProLogic II. 
6cd537c For mobile platforms, the only output modes supported are mono and stereo.
6cd53c7 EVENT_SETMODE
6cd53d5 SetModeParam
6cd53e2 Set Mode
6cd53eb The set mode event allows a game to set the Dac output to a new output mode.
6cd5439 If the specified output mode is not supported on the given platform/configuration, the next most logical output mode will be notched down to and selected automatically. For most platforms, this means the output mode could always be set to 7.1 if desired and the closest supported mode will be selected. The output mode should ideally be set before the Dac is started. However it can be changed while the Dac is running without any lasting side effects to the EAAudioCore code or game code on PC and PS3. The audio output will be interrupted for a brief period, which can sound disconcerting. If this is an issue the signal on the mastering voice could be faded down and back around the switch by manipulating a fader PlugIn appropriately. For iOS the output mode must be set before the Dac is started.
6cd575c For the Xbox 360, XBox One and PS4 all output mode selection is handled via the dashboard. For XBox 360 EAAudioCore always feeds a 5.1 signal to the console and it will down-mix or encode the audio into the format the user has selected. On XBox One and PS4 the same happens except with a 7.1 signal feed to the console.
6cd589d Unlike the other consoles, the PS3 does not automatically encode audio into the format the user has selected in the OSD.EAAudioCore looks at what audio output modes are set up in the OSD and selects the one it determines will yield the highest quality results. The selection criteria first attempts 8 channel modes, 6 channel modes, and then 2 channel modes. Within each channel selection it will attempt the encoding method that introduces the least distortion into the signal. Given only some of the OSD modes are supported this effectively results in the order of selection being HDMI 7.1, HDMI 5.1, HDMI or optical Dolby Digital 5.1, HDMI or optical DTS 5.1, then HDMI or optical or analog stereo. 
6cd5b5d On the PS3 the SETMODE event is respected in the specific case of selecting a Dolby Pro Logic II output versus plain stereo when the user has selected a stereo output via the OSD. The OSD and Sony libraries lack native support for PL2. Some game teams have requested PL2 support on PS3 so EAAudioCore provides it via its own encoder. Unfortunately there is no way to select PL2 in the OSD as it doesn't support it, and so switching between stereo and PL2 must be managed by calling SETMODE with either MODE_STEREO or MODE_PROLOGIC2. In this situation the SETMODE event acts more like a hint than an absolute setting. MODE_STEREO or MODE_PROLOGIC2 will only be respected if the OSD is set to output stereo. Setting of other modes will be ignored. For example, setting MODE_5POINT1 is meaningless as EAAudioCore only respects the OSD when determining non-stereo output modes.
6cd5ec8 A PS3 game that wishes to support PL2 is faced with one of two choices on how to know when to enable it. The game code could have a front end menu option to allow the user to select between stereo and PL2. This is however very ugly to the end user as they now have to configure audio output in more than one place. The option is also confusing as it doesn't force stereo or PL2 mode if the OSD is set to a 5.1 or 7.1 output mode. For these reasons a menu option is not recommended. The better alternative is to decide up front if your game will always output either plain stereo or PL2. This would probably be the audio director's choice based on what they prefer.
6cd6162 On the PC platform, note that some output modes are not reliable, even if they are enumerated as supported (e.g., quad, 5.1 and 7.1). Although everything may appear to work correctly when interfacing with EAAudioCore, the user may experience crackling audio or missing channels for example. For that matter the quad, 5.1, and 7.1 modes will almost always be enumerated as supported even if the user only has two speakers. As the quad, 5.1, and 7.1 modes cannot be counted on to work on every machine, the game must provide an option to let the user switch between stereo, quad, 5.1, and 7.1 modes. It is also a bonus to the user if an audio testing screen is included where a sound is played in turn on all channels. This way the user can determine if the quad, 5.1, or 7.1 modes will work properly for them in the game.
6cd6498 For iOS the only mode supported are stereo and mono.
6cd64ce For Android, the output mode selection is handled via Java code AndroidEAAudioCore.Startup (channels).When a channel configuration with more channels than what the output is set to is fed to the Dac, it will perform an industry standard fold-down to the required configuration (5.1, quad, stereo or mono). Even if the Dac PlugIn is not performing the fold-down, the PC or console platform might be performing a fold-down on its end. Hard clipping can be introduced during the fold-down if the signal coming into the fold-down is loud. Although the hard clipping should not be as audible a problem as it might sound, it can be avoided by reducing the volume of the signal before it goes into the Dac PlugIn. If a signal is normalized to full scale (+/- 1.0) before it enters the Dac PlugIn by a PlugIn such as a compressor, then when folding down to quad or stereo, reducing the signal to approximately 45% (-6.9 dB) of its original level will ensure no hard clipping will occur. On the other hand, hard clipping noise is not as noticeable as one might think. Furthermore, given that it may be quite unlikely that the mix will be driven in game to produce the extreme configuration required to produce the maximum peak (greater than +/- 1.0) after fold-down, it is suggested that users not worry too much about clipping possibilities, especially since the additional reduction of volume to avoid it may result in the game output being too quiet.
6cd6a75 EVENT_START2
6cd6a82 Start2Param
6cd6a8e The start2 event tells the Dac PlugIn to begin operation. The Dac can be started either in offline mode or realtime mode, the latter being the norm. When started in realtime mode, the Dac will begin driving the EAAudioCore mixer process and outputting the resulting sample data to the speakers. This driving of the mixing process will either be indirect via the user thread when running in System Jobs mode with User Scheduling, or direct via a Dac thread otherwise. When started in offline mode, the Dac will enter a state where mix frames are processed as a result of the EVENT_OFFLINEMIXFRAME event in the case of Non-System Jobs Mode, and via System::ScheduleJobs() in the System Jobs Mode case. In offline mode, sample data is not output from the Dac. Users who wish to use the audio data that is produced when in offline mode should use the SampleCapture or AiffWriter PlugIns, or a suitable replacement.
6cd6e1e The start2 event must be called in order for any EAAudioCore playback to occur. The Dac is not started upon instantiation.
6cd6e9a On the PC platform, it is possible that no sound card is installed on a machine or the sound system is not working for some reason. When this happens, the Dac provides functionality to "pretend" that it is operating normally as if a sound card is present. EAAudioCore will act as if nothing is wrong. This functionality is provided so that game programmers can handle the missing sound system with ease. The less appealing alternative would be to have special code inserted everywhere to handle EAAudioCore API functions not working as expected.

The object position, gain and other attributes are preserved as metadata and passed along with the mono audio waveform data to the Sony Audio3D library API which will either pass it on to a 3D Object Audio capable receiver or to headphones if connected, or render the audio to a 7.1 mix for output along with the rest of the audio mix. In the case of a 3D Object Audio capable receiver, it is expected that such a receiver would render the object audio based on the speaker configuration it is using, which ideally would include speakers above (and possibly below) the plane in order to experience more accurate 3D sound. In the case of headphones, head-related-transfer-function (HRTF) techniques could be used to render the audio in 3D. Note that the mixer sample rate must be set to the default 48 KHz value (which is the output sample rate of the PS4) because Object3DOutput does not resample the mix to the hardware output rate. Thus the System must be run at the same rate as the hardware in order for the PlugIn to work. For more information on this functionality, please refer to the PS4 Audio3D library documentation.

6ceb828 The Pan2D1 PlugIn allows for panning of a signal, with speakers pre-positioned at fixed locations on the edge of the circle according to the number of output channels. The power will be distributed between the speakers based on panangle, pandistance, pansize, and pantwist parameters relative to the listener's position at the center of the circle.
6ceb986 The geometry of the panner can be over-ridden once in game code by calling EA::Audio::Core::Pan2D1::SetDefaultFrontSpeakerAngle(),  EA::Audio::Core::Pan2D1::SetDefaultRearSpeakerAngle(), and EA::Audio::Core::Pan2D1::SetDefaultFarRearSpeakerAngle(). 6cebb06 By default the front speakers are set 30 degrees from front center, the rear speakers are 110 degrees from front center, and the far rears at 150 degrees from front center. If users want a configuration specific to a given output channel configuration, they should set the speaker locations either via calling the aforementioned SetDefaultFront/Rear/FarRearSpeakerAngle() functions, or by using the constructor parameters. For example, users may want a 7.1 channel configuration where the front, rear, and far rear speakers are equidistant. Such an equidistant relationship provides some nice benefits when rotating multi-channel content around in a circle, as it means a stereo image with 60 degree separation can be rotated to emanate from any two speakers without bleeding of the image, assuming the centre level of the panner is set to 0. If the voice outputs 5.1 channels (i.e., the voice containing this panner has 6 output channel rather than 8), then for the same equidistant properties, values of 45 and 135 degrees should be used for the front and rear speaker geometries respectively. 
6cebfaa For all source channel configurations, the front, rear, and far rear source geometry can be adjusted independent of the speaker geometry. By default, the source geometry is the same as the speaker geometry.
6cec07a For speaker configurations that include a LFE channel, the PlugIn will pass through the incoming LFE channel by ATTRIBUTE_SETLFEPASSTHROUGHLEVEL. 6cecbd6 Panner (3D)
6cecbe2 The Pan3D PlugIn allows for spatializing a mono signal over stereo, quad, 5.1 , or 7.1 channel configurations. The PlugIn is intended for use in conjunction with a higher level 3D audio application such as the EAAudio3D (or EAAudioSimple3D) library. This higher level library is responsible for producing a set of path parameters (delay amounts, azimuths, gains, filter cutoffs, etc.) for a direct path and several indirect paths which are to be used by Pan3D in spatializing the input signal.
6cecdd1 The geometry of the panner can be over-ridden once globally in game code by calling EA::Audio::Core::Pan3D::SetDefaultFrontSpeakerAngle(),  EA::Audio::Core::Pan3D::SetDefaultRearSpeakerAngle(), and EA::Audio::Core::Pan3D::SetDefaultFarRearSpeakerAngle(). The geometry can also be over-ridden on a per instance basis by setting the appropriate angle-based constructor parameters of Pan3D. By default the front speakers are set 30 degrees from front center, the rear speakers are 110 degrees from front center, and the far rears at 150 degrees from front center. This provides a reasonable compromise for operation in quad/5.1 channel cases versus 7.1. If users want a configuration specific to a given output channel configuration, they should set the speaker locations either via calling the aforementioned SetDefaultFront/Rear/FarRearSpeakerAngle() functions, or by using the constructor parameters.
6ced157 The Pan3D PlugIn consists of an interpolating multi-tap delay line, several filters, and Vector Base Amplitude Panners (VBAP) for direct and indirect path types. The length of the delay line is determined by the constructor parameter CONSTRUCTORPARAM_MAXDELAY, and the maximum number of indirect paths and corresponding read taps is determined by the constructor parameter CONSTRUCTORPARAM_MAXINDIRECTPATHS. It is possible that the higher level 3D audio application sends less indirect paths than the maximum, though sending more will result in some paths not getting played. The positions of the read taps are determined by the delay values of the direct and indirect paths. The input audio signal is first read either directly from a tap, or via interpolation (two-point linear) in the case of a changing delay and corresponding Doppler shift. It then passes through a low pass filter, followed by a low shelving filter in the case of the direct path only, and finally into a type of VBAP panner. The low pass filter simulates air and surface absorption effects while the low shelving filter models the proximity effect. The VBAP panner maps the direct path azimuth to gain values for each of the five main channels in the 5.1 setup to allow for a smooth panning transition when the sound emitter is very close to the listener. The indirect paths use two channel panning on the assumption they generally originate from far away, thereby reducing the amount of processing needed.
6ced721 The Pan3D PlugIn accepts a mono source as the input signal and produces up to an 8 channel output. If rendering of stereo or multichannel sources is required, the user will have to first split the input into multiple mono sources.
6ced809 Pan3D can be CPU intensive if a large number of indirect paths are being processed. The PlugIn can require a large amount of memory as well, depending on CONSTRUCTORPARAM_MAXDELAY and the number of indirect paths used, and therefore it is good practice to understand how much of the system resources can be allocated to Pan3D before choosing these values.
6ced96e For more information on 3D audio calculation and rendering, please see the EAAudio3D package documentation and library. Also, please refer to the EATech 3D Audio Solution white papers and presentation on EA Knowledge at: http://www.worldwide.ea.com/articles/view.aspx?id=2770 .

6cf398a Reverb (Impulse Response)
6cf39a4 The ReverbIR1 PlugIn provides an efficient method for applying the reverberation characteristic of a given space to the game audio signal. This is achieved by performing the fast convolution of the audio signal with the impulse response (captured or created) of a given reverberant space. The efficient implementation is achieved by performing the convolution in the frequency domain, after having first sectioned the impulse response into smaller pieces in order to minimize delay and memory usage. To apply a given impulse response (IR), a corresponding impulse response file (such as say a stereo .wav file that contains the IR) must first be converted to an irf file (via SIMEX/SX). This file must be at the same sample rate as the output rate used in the game. The response is then applied to the signal via the EVENT_APPLYREVERB event.
6cf3cef While the PlugIn has been designed for efficient operation, it does still require considerable resources, especially memory. To help mitigate this, memory usage can be traded off against the high frequency content of the reverberated signal retained. This is specified when creating the impulse response file (irf) via the SIMEX/SX parameter percentHighFrequencyCut. Reductions in memory usage will be nearly proportional to the number specified (i.e., if 50.0 is specified, memory usage will go down by close to half). This also results in considerable cycle savings. Additionally, cycle usage can be traded off against delay with the SIMEX/SX parameter samplesPerFFTBlock, which allows for specification of the FFT block (segment) size. Larger sizes result in more efficient processing at the expense of added delay. Sizes used by the FFT must be a power of 2, so any sizes specified that aren't will be forced to a power of 2. On the PS3 platform the block size is limited to a maximum of 1024 samples, which is large enough to achieve very good efficiency while not adding too much delay. 
6cf4136  The ReverbIR1 PlugIn supports the use of two impulse responses at the same time. This allows for efficient cross fading from one environment to another, or the blending of two environments to create a third. This is immensely more efficient than using two separate ReverbIR voice instances, as the extra amount of memory and cycles required to support two reverbs rather than one within the PlugIn is very small. To utilize this feature, users must simply specify the reverb number (APPLYREVERBPARAM_REVERBNUMBER) along with the impulse response file (APPLYREVERBPARAM_REVERBFILE) when applying the reverb with the apply reverb event (EVENT_APPLYREVERB). In addition, to set the relative level of each reverb file the associated gain attribute should be set (i.e., ATTRIBUTE_REVERB0GAIN for reverb 0). Users must also ensure that any impulse response files being simultaneously used have the same number of channels, samples per block, and high frequency cut values.
6cf44ff The ReverbIR1 PlugIn also supports the enveloping of either or both of the impulse responses. This allows for the possibility of shortening a given impulse response by fading it out to zero over a specified amount of time (i.e., ATTRIBUTE_REVERB0ENVELOPELENGTH for reverb 0).A start gain and envelope shape also must be specified via attributes (i.e., ATTRIBUTE_REVERB0ENVELOPESTARTLEVEL and ATTRIBUTE_REVERB0ENVELOPETYPE for reverb 0 respectively). This enveloping feature should be used with care, as the artificial shortening of an impulse response with a ramp does not exactly reflect a real-world scenario. If employed, users should experiment with the various enveloping parameters and impulse response(s) to confirm the resulting reverb suits their needs. The potential benefit with the use of enveloping is that it provides the user with some control over a given impulse response, allowing for greater variability and/or the use of less impulse response files. In the extreme, a user might use a single long impulse response, and simply adjust its length via enveloping to tailor it to the various reverberent spaces of the game. Combining enveloping with the use of two active individually gained reverb files can result in a high degree of flexibility and real-time creative control. 
6cf4a10  To help minimize memory fragmentation due to allocations made internally by ReverbIR1, the constructor parameter CONSTRUCTORPARAM_MAXREVERBLENGTH has been provided. Users should set this to the longest impulse response (in seconds) used in their game if they want to minimize memory reallocations. If interested in further minimizing reallocations, users are advised to alternately use reverb slots 0 and 1 as they move from one impulse response file to the next. Not only does this allow cross fading from one to the other via the gain attributes, but it avoids the memory reallocations that would occur if the same slot were used. Specifically, when only a single reverb slot is being used/reused, ReverbIR1 does not insist that a newly applied reverb file be configured identically to the previous one, thereby allowing for a change in configuration if this is required. However, if slots are being alternately used (with some non-zero time overlap), then since this implies they must be configured the same, there does not need to be any memory reallocation (as long as the reverb files are never larger than the largest reverb used thus far and/or the value set in the constructor parameter CONSTRUCTORPARAM_MAXREVERBLENGTH). Also note that an EVENT_STOPREVERB1 event need not be used prior to applying a new reverb file, as the application of the new reverb file will result in the previous one not being accessed further by the ReverbIR1 instance. One reason to apply the stop event would be if there was some time during which only one reverb was needed, especially if the next reverb needed was not yet known. However, as long as slots are alternated and at least one slot is always active, use of the stop event should not cause additional reallocations.
6cf50f7 The ReverbIR1 PlugIn supports several channel-impulse response file configurations. 1:1 source to output channel mappings (1, 2, 4, 6 or 8 channels) are supported, where the impulse response file is either mono, or it is comprised of the same number of channels as the signal input. Also, a 1:n source to output channel configuration is supported (1, 2, 4, 6 or 8 output channels), where the impulse response file is comprised of n channels.
6cf52b2 Since the ReverbIR1 PlugIn will tend to be used as a global effect, and also since it will in some cases produce a different number of channels than are fed to it, the PlugIn is configured so that it will return silence when inactive. Normally, a separate parallel path would exist that persists even when the reverb is off, providing the dry, non-reverberated audio signal.
6cf542a Also note that most impulse response files will have some gain associated with them. If this is significantly larger than one and the PlugIn input signal is also fairly large, the ReverbIR1 output will most likely get clipped in the mastering voice, causing distortion. This can be avoided by decreasing the send level into or out of the ReverbIR1 voice, or by reducing the level via a gain PlugIn within the ReverbIR1 voice.

6cfb92a Sample Player
6cfb938 The SamplePlayer PlugIn is a general purpose player which is designed to be format agnostic. Using the EA::Audio::Core::ISampleReader interface, the player is capable of playing from any compressed data source for which an implementation has been provided. Currently we've only provided a reader for the sps file format to allow playback of SndPlayer1 assets. But future releases may also provide readers for generic user content, packet streams, and more.
6cfbb02 The SampleReader PlugIn is capable of looping, seeking, and stitching but is limited by reader implementations and the file formats involved. For example, looping and sample accurate stitching works well with sps data, but would be problematic for conventional MP3 data.
6cfbc12 A SampleReader instance can output a dynamic number of channels (between 1 and the number of output channels it was created with). It is suggested that the player be followed by a Rechannel PlugIn when dealing with multiple source asset channel configurations on a single player.
6cfbd2b The SamplePlayer PlugIn, although functionally very similar to the SndPlayer1 PlugIn, has some key API differences that users should be aware of. Firstly, attributes are now updated from the mixer thread in lock free mode as is typical for most PlugIns. This is unlike the SndPlayer1 and the GenericPlayer PlugIns which update their attribute values from within a timer client. The difference here is that attribute values may not always appear to be consistent with each other. For example, a client holding the lock may read one attribute, then the mixer thread updates the voice attributes without holding the lock, and then the client reads a second attribute before releasing the lock. The client will not see invalid values but there is no guarantee that they all came from the same mixer frame. In other words, the attributes may not be mutually consistent. Although, the approach taken with the SamplePlayer may be more complex, the advangage is that the player implementation may suspend its PPU timer client execution much of the time to save CPU cycles.
6cfc155 Users should avoid cases where reading mutually consistent attributes is required. The SamplePlayer provides the following new attributes to handle the most common cases where reading multiple was typically required:
6cfc22e    - the ATTRIBUTE_GETTIMEREMAINING attribute can be used to avoid needing to read both the position and length values atomically.
6cfc2b1    - the ATTRIBUTE_GETPROGRESS attribute can be used to avoid needing to read both the position and length values atomically.
6cfc32f    - the ATTRIBUTE_GETCURRENTREQUEST attribute can be used alone to determine whether a given request handle has been completed or not (since the player will advance past the last request by 0.5f when idle).

6d01bc5 SND Player
6d01bd0 The SndPlayer1 PlugIn is the main player used for game audio sample playback. It efficiently supports resident RAM samples, streamed samples, gigastream samples, stitched playback, looped samples, sample accurate starting, up to 64 channels, and multiple compression types.
6d01ce3 Looping samples will repeat their loop section infinitely, there is no lead-out section present which can be triggered.
6d01d5c When stitching, the samples being stitched can be in any format (different sample rates, compression types, number of channels), and the joining of two samples will still be seamless.
6d01e15 A SndPlayer1 instance will output a variable number of channels equal to the number of channels int the source sample data. In order for a single voice to handle assets with differing channel configurations, it will need to be followed by a PlugIn which provides a constant number of channles as output such as Rechannel (for standard fold-up or fold down behaviors) or MapChannels (for simple copy, clear behaviors). For more details on their precise behaviors, please see the documentation those PlugIns. To determine the number of channels in an SndPlayer1 asset at runtime you can use the static member function SndPlayer1::GetFileInfo()
6d02098 Gigastream formatted samples are those where a small portion of the beginning of a sample is always stored in RAM, and the rest is stored on media such as DVD. The idea is to allow a sample to begin with no delay as if it was in RAM, but also allow the sample to be as long as desired without consuming any RAM besides the small beginning part in RAM. The small part of the file stored in RAM gives the SndPlayer1 time to retrieve the next portion off of DVD. This means that the length of sample in RAM must be longer than the length of time it takes to retrieve more data off of DVD, under all game conditions where heavy stream load is occurring. The amount of sample data in RAM is chosen at the time the SndPlayer assets are created. You may need to experiment with the length of the data in RAM, a good starting point is about 1 second of sample data.
6d023f3 SndPlayer1 is one of the few PlugIns that supports non-standard channel configurations (up to 64). The Route PlugIn can be used to bus selections of channels to SubMix PlugIns, which can be useful for efficiently streaming layers of interactive music or ambience. For example, a stream file could be authored that contains 4 intensities of stereo crowd ambience. The 8 channel SndPlayer1 output can be routed into 4 stereo SubMixes, and then each SubMix Voice can vary its volume appropriately to cross-fade between the 4 intensities. This approach may use more CPU time than other approaches, but streaming a single 64 kilobyte/s stream will be far easier on a DVD than streaming 4 16 kilobyte/s streams. In most cases DVD bandwidth will be far more scarce than CPU bandwidth.
